## Purpose

Define expected behavior for reporting multi-currency (USD and EUR) exchange-rate data in the finance command output, including resilience and transparency requirements. This is the living specification for the finance feature module.

## Responsibilities

- Report USD and EUR exchange-rate data through the `/dollar all` command.
- Render `/dollar all` responses as an image (PNG attachment) generated by `internal/imagegen`.
- Preserve available data when one upstream source fails.
- Make each displayed dataset's source and freshness visible.

## Rules

When upstream data is available, `/dollar all` includes both USD and EUR exchange-rate information rendered as cards in a single image.

### Scenario: USD and EUR are both available
- **GIVEN** the USD and EUR upstream endpoints both return valid responses
- **WHEN** a user executes `/dollar all`
- **THEN** the response contains a PNG attachment with one card per rate (USD rates first, then EUR)
- **AND** each card shows the rate name, average value in bolívares, source, and update timestamp

The command returns available exchange-rate data even when one upstream currency source fails.

### Scenario: EUR source fails and USD source succeeds
- **GIVEN** the USD upstream endpoint returns valid data
- **AND** the EUR upstream endpoint is unavailable or returns invalid data
- **WHEN** a user executes `/dollar all`
- **THEN** the response includes a PNG attachment with the USD rate cards
- **AND** the image includes a note indicating that EUR data is temporarily unavailable

### Scenario: USD source fails and EUR source succeeds
- **GIVEN** the EUR upstream endpoint returns valid data
- **AND** the USD upstream endpoint is unavailable or returns invalid data
- **WHEN** a user executes `/dollar all`
- **THEN** the response includes a PNG attachment with the EUR rate card
- **AND** the image includes a note indicating that USD data is temporarily unavailable

### Scenario: all upstream sources fail
- **GIVEN** both upstream endpoints are unavailable or return invalid data
- **WHEN** a user executes `/dollar all`
- **THEN** the command responds with a plain text error message and no image

Displayed currency data includes source and update-time context.

### Scenario: Display metadata for each currency dataset
- **GIVEN** one or more currency datasets are available from upstream APIs
- **WHEN** a user executes `/dollar all`
- **THEN** each rendered card includes data-source labeling
- **AND** each card includes the dataset's update timestamp formatted as `D Mes YYYY, HH:MM AM/PM` with Spanish month abbreviations

Image generation failure must never make the command worse than the embed-based response it replaced.

### Scenario: image rendering fails
- **GIVEN** at least one upstream source is available
- **AND** image generation returns an error
- **WHEN** a user executes `/dollar all`
- **THEN** the command responds with the embed-based representation of the same data

## Boundaries

- Mapping from `DolarResponse` data to image cards lives in `dollar_card.go`; rendering lives in `internal/imagegen`.
- The embed-based response is retained only as a rendering fallback.
